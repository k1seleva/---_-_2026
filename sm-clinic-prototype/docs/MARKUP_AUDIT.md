# Аудит разметки и аналитики протоколов

4 октября 2026. Проверены код конвейера, хранение данных, подсветка в интерфейсе, модель триггеров
и прогон 89 обезличенных протоколов кейса. Прогон локальный: тексты протоколов никуда не выкладывались,
ниже только счётчики и общие слова.

## Как устроен конвейер сейчас

| Шаг | Где | Что делает |
|---|---|---|
| Текст | `processing/services/text_extraction.py` | .docx и .doc в текст, тип и дата исследования, номер карты |
| Находки | `ai_agent.RuleBasedFindingExtractor` | словарь находок (регулярные выражения) только по заключению; одна находка на код; отрицание, сомнение, атрибуты; спан = вся фраза |
| Фрагменты | `segmentation.py`, `annotation.py` | протокол режется на фрагменты без потери текста; у фрагмента вид и причины подсветки |
| Триггеры | `routing/services/matrix.py` | правило матрицы по находке без отрицания; одно правило на клиническую группу |
| Аналитика | `annotation.summary`, `facade.annotation_stats`, `quality.summarize` | счётчики причин подсветки, находок, правил; доля протоколов с правилом |
| Подсветка доказательств | `presenter.evidence_html` | в исходном тексте выделяются фразы находок |

## Что есть и чего нет

| Требование | Есть | Нет или работает неверно |
|---|---|---|
| 1.1 Пайплайн | все четыре шага есть, разметка проверяется инвариантом «ничего не потеряно» | маркеры живут на уровне фрагмента: у причины подсветки нет позиции в тексте |
| 1.2 Нормализация | сравнение цитат без учёта регистра и пробелов (только для проверки ответа ИИ); опечатки вшиты точечно в два шаблона отрицаний | общей нормализации нет: смешанная раскладка, тире, опечатки в названиях признаков не обрабатываются |
| 1.2 Перекрытия | нет | два маркера на одном месте не обнаруживаются; при выводе вторая цитата пропускается |
| 1.2 Уверенность | поле `confidence` у находки | постоянные 0,9 / 0,6 / 0,95, не зависят от контекста; у причин подсветки уверенности нет |
| 1.2 Дедупликация | одна находка на код в заключении | одна и та же находка в описании и заключении, два шаблона на одном месте не сводятся |
| 1.3 Поля триггера | у маршрута код правила, версия и цитата | объекта «триггер» нет: нет id, точной позиции, уверенности, ссылки на правило в одном месте |
| 2.1 Цвета, tooltip, клик | одна жёлтая метка, подсказка браузера | нет цветов по типам, нет выделения триггеров, нет связи с итогами |
| 2.2 Перекрытия в подсветке | нет | перекрывающиеся цитаты «съедают» друг друга |
| 2.3 Режимы | нет | |
| 3.1 Блок «Выявленные триггеры» | блок «Почему так» (находка, правило, маршрут) | нет таблицы с уверенностью, сортировкой и переходом к тексту |
| 3.2 Сводка | доля протоколов с правилом на странице качества | нет числа триггеров по типам |
| 4 Советы Qwen | извлечение фактов через LangChain (по умолчанию выключено) | советов по маршрутизации нет совсем, таблицы оценок нет |
| 5 API | `/api/v1/processing/documents/`, `quality-runs/` | новых полей нет |

## Что показал прогон 89 протоколов

- 1401 неразрывный пробел, 83 длинных тире, 44 буквы «ё», 5 слов со смешанной раскладкой.
  Одно из них: «TI-RADS», где «Т» кириллическая, поэтому шкала не распознана.
- Опечатки в названиях признаков: «гидросальпингс» трижды (признак не найден), «образованяи», «раширена».
- Пробелы лексикона: «бляшек», «атеросклеротических», «дилатированы» не находятся текущими шаблонами.
- Подсветка доказательств выводит фразу находки целиком; если фразы перекрываются, вторая пропускается.

## Что меняется

1. **Нормализация с картой позиций** (`services/normalization.py`): регистр, «ё», пробелы, тире, кавычки,
   смешанная раскладка, словарь частых опечаток. Поиск идёт по нормализованному тексту, позиции
   возвращаются в исходный, поэтому подсветка точная.
2. **Маркеры** (`services/markers.py`): каждый найденный признак с типом, позицией, текстом, уверенностью
   и ссылкой на правило. Уверенность складывается из понятных поправок (сомнение, опечатка, раздел),
   каждая поправка сохраняется и видна в подсказке.
3. **Перекрытия**: одинаковые маркеры сливаются, вложенные получают слой и ссылку на родителя,
   признак внутри находки словаря помечается как поглощённый (виден, но не считается дважды).
4. **Триггеры**: запуск маршрута (правило матрицы), экстренная находка (словарь), нужна проверка
   (изменение не вынесено в заключение). У каждого id, тип, позиция, цитата, уверенность, правило;
   один и тот же триггер из нескольких мест сводится в один с дополнительными цитатами.
5. **Подсветка**: текст режется на непересекающиеся кусочки по всем границам маркеров, у каждого кусочка
   список слоёв. Цвета по типам (контраст по WCAG AA проверяется тестом), триггеры с фоном,
   подчёркиванием и номером, подсказка, клик ведёт к триггеру, три режима показа.
6. **Итоги на карточке протокола**: блок «Выявленные триггеры» сверху, сводка по типам, сортировка,
   переход к месту в тексте. В отчёте «Качество разбора» и в «Признаках и проверках» добавлено число
   триггеров по типам и доля протоколов с триггером.
7. **Советы агента по маршрутизации**: отдельный блок с пометкой «рекомендация ИИ, требует проверки
   координатором». Оценка «принять / отклонить / скорректировать» с комментарием пишется в отдельную таблицу.
   Без подключённой модели работает демо-режим с явной пометкой.
8. **Совместимость**: старые поля API не меняются, новые добавлены рядом. Старые протоколы получают маркеры
   и триггеры при первом открытии.

## Гибридный разбор: словарь и Qwen вместе

Когда задан `LLM_PROVIDER`, каждый протокол размечают оба: словарь и модель. У каждой находки, маркера и
триггера записано, кто его нашёл (`rules`, `both`, `llm`). Найденное только моделью вынесено в отдельный блок
«Найдено только Qwen» с пометкой «словарь этого не нашёл, проверьте», в тексте обведено пунктиром с меткой
«ИИ». Ограничения ИИ те же: только дополнение и только с дословной цитатой, снять подсветку словаря модель не
может. «Качество разбора» и `evaluate_protocols` считают триггеры и маркеры по источникам и сколько раз
модель ответила или упала, так что вклад модели виден на всей пачке.

Блок «Рекомендации агента по маршрутизации» показывает ответ модели: советы после проверки цитат, ответ
целиком и время ответа. Если модель не ответила, видна причина и кнопка «Спросить Qwen ещё раз», демо-советы
не подставляются.

Прогон 89 протоколов выше сделан словарём. С моделью его нужно повторить на компьютере, где развёрнут Qwen:
`python manage.py check_llm`, затем `evaluate_protocols` по той же папке.

Что ещё не закрыто: точность и полноту триггеров можно посчитать только после разметки протоколов
медицинским экспертом (`labels.csv`). Связка с моделью проверена через имитацию сервера Ollama (тот же
HTTP-протокол); на настоящем Qwen не запускалась, так как в среде разработки модели нет.
