# СМ-Клиника · Маршрут пациента (прототип)

Django + DRF + Celery + LangChain. Распознаёт клинически значимые находки в протоколах исследований
и ведёт пациента по циклическому маршруту: уведомление → запись → приём → решение врача →
госпитализация → операция → выписка → контроль → наблюдение.

Для врача значимое в протоколе подсвечивается (находка, размер, сторона, порог, «не вынесено в заключение»),
но не ранжируется: порядок — как в протоколе, наверх врач выносит то, что важно ему (закрепления и личные
приоритеты). Текст сохраняется полностью, каждый фрагмент показан ровно один раз. Рекомендации врача
сверяются с показаниями по находкам: забытая консультация специалиста уходит на обсуждение координатору.
ИИ-агент работает только с текстом протокола: без дословной цитаты ответ отбрасывается, снять подсветку
правил или скрыть фрагмент он не может.

Разметка протокола идёт по шагам: извлечение текста → маркеры (находка, шкала, признак, размер, сторона,
неуверенность, отрицание…) → триггеры (маршрут, экстренное, проверка) → сводка. У каждого маркера и триггера
есть позиция в тексте, цитата, уверенность с разбором факторов и ссылка на правило (`dictionary:…@v3`,
`matrix:…@v1`). Подсветка различает типы цветом (контраст WCAG AA), триггеры выделены сильнее (фон,
подчёркивание, метка Т1…), наложения не теряются, есть режимы «все маркеры», «только триггеры», «только тип».

Если подключён Qwen, протокол размечают вместе словарь и модель. У каждого маркера, находки и триггера указано,
кто его нашёл: «словарь и Qwen согласны», «только словарь» или «только Qwen». Найденное только моделью
показано отдельным блоком «Найдено только Qwen» (триггеры и признаки), а в тексте обведено пунктиром с меткой
«ИИ» и включается режимом подсветки «Только найденное ИИ».

Отдельно от аналитики, в блоке «Рекомендации агента по маршрутизации», Qwen предлагает маршрут с
обоснованием и цитатой; под советами виден ответ модели целиком и время ответа. Каждый совет помечен «рекомендация ИИ, требует проверки координатором», координатор
принимает, отклоняет или корректирует его с комментарием; оценки хранятся в отдельной таблице.

Архитектура, схемы и модель данных — в [ARCHITECTURE.md](ARCHITECTURE.md).
За что отвечает каждый файл — в [FILES.md](FILES.md).

## Быстрый старт (без Docker, без Redis, без LLM)

```bash
python -m venv .venv 
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
cp .env.example .env            
python manage.py migrate
python manage.py seed_demo      # словари, матрица, шаблоны, врачи, расписание, демо-пациенты, сводка прогона
python manage.py createsuperuser  # для /admin (настройки матрицы и текстов)
python manage.py runserver
```

Откройте http://localhost:8000 — роли: «Пациент», «Координатор», «Врач».
Кнопки «+24 ч», «+72 ч», «+7 дн», «+30 дн» в шапке сдвигают модельное время и прогоняют эскалации.

**Только реальные цифры.** Синтетические протоколы в базу по умолчанию не попадают: аналитика считается по
протоколам, которые вы загрузили («Протоколы», «Качество разбора», папка `inbox`). `seed_demo` подгружает
сводку прогона 89 обезличенных протоколов кейса (`docs/case_run_summary.json`, только счётчики, без текстов
и имён файлов); она видна в «Аналитике» и «Качестве разбора». Обновить сводку после своего прогона:

```bash
python manage.py evaluate_protocols ./data/protocols --out report.csv \
    --summary-json docs/case_run_summary.json --title "Протоколы кейса"
python manage.py import_run_summary docs/case_run_summary.json
```

`demo_batch` (синтетический поток для разработки) запускается только с флагом `--i-know-it-is-synthetic`.

**Три роли, у каждой свой вход.** Пациент входит по номеру амбулаторной карты и паролю на `/patient/` и видит
только свой кабинет. Координатор входит на `/coordinator/login/` (входящие, маршруты, задачи, загрузка, аналитика).
Врач входит на `/doctor/login/` и видит только своё расписание и свои приёмы. Роль сотрудника задаётся группой
учётной записи Django (`coordinator` или `doctor`), врач привязан к своей карточке (`Doctor.user`); раздел чужой
роли не открывается. После 5 неверных попыток вход под этим логином или картой закрывается на 15 минут.
Демо (создаёт `seed_demo`): пациенты `AK-0001`…`AK-0008`, координатор `coordinator`, врачи `doctor1`…`doctor9`,
пароль у всех `demo-2026` (`PATIENT_DEMO_PASSWORD`, `STAFF_DEMO_PASSWORD`). `createsuperuser` может войти в любую
роль сотрудника. API `/api/v1/` в прототипе по-прежнему открыт для интеграции (кроме данных пациента).

## Qwen: словарь и модель вместе

1. В `.env` (образец и варианты в `.env.example`):

   ```bash
   LLM_PROVIDER=ollama
   LLM_MODEL=qwen2.5:14b              # имя как в `ollama list`
   LLM_BASE_URL=http://localhost:11434
   LLM_NUM_CTX=8192                   # окно контекста: у Ollama по умолчанию 2–4 тыс., протокол обрезается
   LLM_TIMEOUT_SEC=180
   ```

   LM Studio, vLLM и другие OpenAI-совместимые серверы: `LLM_PROVIDER=openai`, `LLM_BASE_URL=http://…/v1`,
   `pip install langchain-openai`. Если приложение в docker compose, а Ollama на компьютере:
   `LLM_BASE_URL=http://host.docker.internal:11434`.
2. `python manage.py check_llm` прогоняет синтетический протокол через все шаги: модель отвечает, находки
   заключения (словарь и модель), разметка фрагментов, маркеры и триггеры по источникам, советы с ответом
   модели целиком. Ничего не сохраняет. Свой текст: `--text протокол.txt`.
3. Протоколы, загруженные до подключения модели, размечены только словарём: загрузите их заново.
   Советы для них можно получить кнопкой «Получить ответ Qwen» на странице протокола или
   `python manage.py regenerate_advice` (только где советы демо-режима или с ошибкой; `--all` — все).

Что делает модель. Находки заключения: словарь и модель отвечают независимо, совпавшее получает источник
«оба», найденное только моделью добавляется с дословной цитатой. Разметка фрагментов: модель может только
добавить подсветку (с цитатой из фрагмента), снять подсветку словаря не может. Ответ без цитаты, с кодом вне
словаря или числом, которого нет в тексте, отбрасывается. Если модель не ответила, протокол разбирается
словарём, а причина («нет связи с сервером модели», «не ответила за 180 с», «модель не найдена») видна над
таблицей триггеров.

Советы по маршрутизации: `ROUTING_ADVISOR_MODE=auto` спрашивает ту же модель, если задан `LLM_PROVIDER`
(свою модель для советов можно задать `ROUTING_ADVISOR_PROVIDER`, `ROUTING_ADVISOR_MODEL`,
`ROUTING_ADVISOR_BASE_URL`). Если модель не ответила, на странице видна ошибка и кнопка «Спросить Qwen ещё
раз»: демо-советы вместо ответа модели не подставляются. Без провайдера работает демо-режим: советы собираются
из триггеров и так и подписаны. `off` выключает блок. Каждый совет проверяется по тексту (цитата найдена,
маршрут и специальность есть в справочнике), маршрут по совету сам не меняется.

Без модели интерфейс можно посмотреть с имитацией сервера Ollama (ответы по правилам, это не Qwen):
`python tests/fake_ollama.py --port 11500` и `LLM_PROVIDER=ollama LLM_MODEL=qwen-fake
LLM_BASE_URL=http://127.0.0.1:11500`.

## Загрузка папки протоколов: фоновая очередь

С моделью протокол разбирается минутами, поэтому загрузка пачки только сохраняет файлы и сразу открывает
«Входящие». Протоколы разбираются в фоне по одному, во «Входящих» видны полоса хода, сколько в очереди,
какой файл сейчас у модели, среднее время и оценка остатка; страницу можно закрыть. Советы ИИ по
маршрутизации идут после того, как разобраны все протоколы пачки (координатор раньше получает разбор).
Пока очередь не пуста, в шапке любого раздела рабочего места видно «Идёт разбор: N протоколов» со ссылкой
на ход пачки.

* Очередь (`PROCESSING_QUEUE`): `thread` по умолчанию без Redis (фоновый поток сайта, задачи хранятся в базе,
  после перезапуска сервера очередь продолжается сама); `celery` в docker compose (воркер `worker-llm`,
  очередь `llm`, по одной задаче на процесс); `sync` только для отладки. Команды `manage.py` разбирают сами.
  Отдельный обработчик без Celery: `python manage.py process_queue` (`--once` разобрать очередь и выйти).
* Сколько протоколов одновременно: `PROCESSING_WORKERS=1`. Больше ставить, только если сервер модели
  отвечает параллельно (у Ollama `OLLAMA_NUM_PARALLEL`), иначе запросы ждут друг друга и падают по тайм-ауту.
  При `LLM_PARALLEL_CALLS=2` находки и разметка одного протокола запрашиваются одновременно.
* Модель не ответила (тайм-аут, нет связи): на `LLM_COOLDOWN_SEC` её не спрашивают, очередь ждёт до
  `LLM_WAIT_MINUTES`, потом протоколы разбираются словарём без ожидания тайм-аута на каждом. Такие протоколы
  помечены «Без ответа ИИ», после пачки их можно отправить кнопкой «Повторить с ИИ»; маршруты не задваиваются.
* Задача, зависшая «в работе» (сервер перезапустили, воркер упал), через `PROCESSING_STALE_MINUTES`
  возвращается в очередь, после двух попыток помечается ошибкой («Повторить неудавшиеся»).
* Быстрее с Qwen: `LLM_REASONING=0` (Qwen3 без «размышлений»), модель остаётся в памяти
  (`LLM_KEEP_ALIVE=30m`), разметка просит у модели метки только для фрагментов с изменениями, длина ответа
  ограничена (`LLM_NUM_PREDICT`). Время каждого шага (`read`, `extraction`, `markup`, `analysis`, `save`)
  сохраняется в задаче и показывается средним по пачке: `GET /processing/batches/<id>/progress/`
  (скриншот `docs/screenshots/24-batch-progress.png`, снят на имитации Ollama и синтетических протоколах).

## Демо-сценарий за 3 минуты

1. «Протоколы» → загрузить .docx с заключением «Эхографические признаки полипа эндометрия» → видно
   разметку «что важно» (карточка с размером и деталями из описания), проверку рекомендаций,
   подсвеченную цитату, правило и созданный маршрут.
   В карточке случая наверху «Выявленные триггеры» (сортировка по уверенности и типу, клик ведёт к месту в
   тексте), ниже подсветка с режимами и подсказками, внизу «Рекомендации агента по маршрутизации» с
   кнопками «Принять», «Отклонить», «Скорректировать».
2. «Пациент» → вход по карте `AK-0001` и паролю `demo-2026` → уведомление с кнопками и пример push на экране
   телефона (врач, дата и клиника ближайшего приёма) → «Выбрать время» → только слоты оперирующего гинеколога.
3. «Врач» → приём: баннер маршрута, без тактики завершить нельзя → «Оперативное лечение показано».
4. «+24 ч» → у координатора задача «Назначить дату госпитализации».
5. События стационара приходят из МИС 1С вебхуком `POST /api/v1/mis/events/`. В прототипе это
   **заглушка**: событие проверяется по контракту и пишется в журнал (`GET /api/v1/mis/events/`),
   данные не меняются. Чтобы события двигали маршрут, запустите с `MIS_WEBHOOK_MODE=live`:
   ```bash
   curl -X POST localhost:8000/api/v1/mis/events/ -H 'Content-Type: application/json' \
     -d '{"event_id":"e1","event_type":"patient.discharged","patient":{"mis_id":"AK-0001"},"data":{}}'
   ```
   В режиме live → новый виток «Послеоперационное наблюдение», контрольный приём записан заранее.
6. «Координатор» → воронка, закономерности, сравнение «ИИ / врач», корректировка маршрута, аналитика
   признаков, «Проверка рекомендаций»: по каждому замечанию «принять» (этап добавляется в маршрут) или «отклонить».

## API (новые поля только добавлены, старые не менялись)

| Запрос | Что возвращает |
|---|---|
| `GET /api/v1/processing/documents/{id}/` | как раньше, плюс `result.analysis` (маркеры, триггеры, наложения, сводка), `result.qwen_advice` и `rule_id` у находок; `source` у находок, маркеров и триггеров (`rules`, `both`, `llm`) |
| `GET /api/v1/processing/documents/{id}/analysis/` | только разметка: `version`, `markers`, `triggers`, `overlaps`, `stats` |
| `GET /api/v1/processing/documents/{id}/advice/` | советы агента со статусом генерации и проверкой по тексту; `raw_answer` (ответ модели целиком), `duration_ms`, `error` |
| `GET, POST /api/v1/coordinator/advice-reviews/` | оценки координатора: `advice_id`, `verdict` (accept/reject/correct), `comment`, `timestamp` |
| `GET /api/v1/coordinator/advice-reviews/stats/` | сколько советов принято, отклонено, скорректировано |
| `GET /api/v1/patients/{id}/…` | только сотруднику или самому вошедшему пациенту; список пациентов закрыт для пациентов |

## Тесты и проверка качества аналитики

```bash
python manage.py test tests
```

**Качество разбора** («Аналитика → Качество разбора», `/processing/quality/`): загрузите до 100
протоколов (файлы, папка или zip) и, по желанию, разметку эксперта `labels.csv` (`file,expected_rules`,
коды правил через «;», пусто — норма). Прогон идёт «всухую»: пациенты, маршруты и уведомления не
создаются, файлы удаляются после проверки. Отчёт: прочитано, разметка без потерь, доля сработавших
триггеров, правила и находки, проверка рекомендаций, подсветки; с разметкой — точность, полнота, F1 и
список расхождений. Отчёт CSV — заодно шаблон для разметки. То же через API:

```bash
curl -F files=@protocols.zip -F labels=@labels.csv localhost:8000/api/v1/processing/quality-runs/
python manage.py evaluate_protocols ./data/protocols --out report.csv [--labels labels.csv] [--with-text] \
    [--summary-json summary.json --title "Название прогона"]
python manage.py quality_sample --out ./quality_sample   # для разработки: синтетический набор + labels.csv
```

Лимит прогона — `QUALITY_MAX_PROTOCOLS` (по умолчанию 100); лишние файлы перечисляются в отчёте.
`evaluate_protocols` делает то же для папки на диске без ограничения числа файлов.

Выданные протоколы не входят в репозиторий (их нельзя публиковать); положите их в `data/protocols/`
(папка в `.gitignore`). Тесты используют синтетические протоколы.

```
                        demo_batch и quality_sample (только для разработки)
apps/
  processing/           загрузка .doc/.docx/.json, извлечение текста, LangChain-агент + правила, находки, подсветка значимого, пачки, проверка качества разбора
    services/           text_extraction.py, ai_agent.py, schemas.py, dictionary.py, pipeline.py,

  routing/              матрица, шаблоны, маршруты, этапы, журнал
    services/           matrix.py, builder.py, planner.py (цикл), state_machine.py, escalation.py
  coordinator/          задачи, споры и корректировки, проекция RouteFact, аналитика, оценки советов ИИ (AdviceReview)
  patients/             пациент, вход в кабинет (services/auth.py), уведомления (ЛК/push/SMS, антиспам),
                        пример push (services/push.py), запись строго по маршруту
  doctors/              специальности, локации, врачи, слоты, записи, итог приёма (тактика), назначения
  audit/                проверка рекомендаций: матрица показаний, достаточность, замечания координатору
  <module>/facade.py    единственный публичный интерфейс модуля для остальных
  <module>/handlers.py  подписки модуля на события
  <module>/api/         DRF: serializers, views, urls
templates/, static/     страницы (токены цвета в static/css/sm.css, подсветка и режимы в static/js/evidence.js)
docs/                   аудит разметки, правила push, сводка реального прогона (только счётчики), снимки экрана
tests/                  извлечение, разметка, маркеры и триггеры, советы ИИ, вход пациента, проверка рекомендаций,
                        полный цикл маршрута, изоляция модулей
```
